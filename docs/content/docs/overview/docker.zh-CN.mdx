# Docker 部署

## 1Panel 静态网站部署（推荐）

主应用是 Vite 静态前端，1Panel 无需安装 Node.js、Bun 或数据库。

1. 在 GitHub 仓库 Actions 中启用工作流，推送 main 后会自动运行 **Build and Release**，也可选择 **Build and Release → Run workflow → main**。成功后下载 `jisu-canvas-web` Artifact，解开外层压缩包，取出 `jisu-canvas-web.zip`。
2. 在 1Panel 安装 OpenResty，创建静态网站，域名填写 `image.jisuai.net`，并将域名 DNS 指向服务器。
3. 上传并解压 `jisu-canvas-web.zip` 到网站根目录，确保根目录直接包含 `index.html`、`assets/` 和 `config.js`，不要多套一层目录。
4. 在站点配置中修改已有的 `location /` 为以下内容（不要重复添加同名 location）：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}

location = /index.html {
    add_header Cache-Control "no-cache";
}

location = /config.js {
    add_header Cache-Control "no-store";
}
```

5. 申请并启用 HTTPS，访问首页以及 `/canvas`、`/config`，刷新子页面确认路由正常。

AI 请求仍由用户浏览器直连 `https://api.jisuai.net`；API 服务的 CORS 需允许网站来源 `https://image.jisuai.net`。将网页放到服务器不会消除跨域。

更新时备份原网站文件，用新包覆盖，并避免让旧页面引用的静态资源立即失效；回滚使用备份。浏览器中的画布、素材和 Key 不随服务器文件部署而迁移。

## GitHub 自动构建与 Releases

日常更新，在项目根目录执行以下命令即可触发云端 ZIP 构建和 Docker 镜像推送：

```bash
git add -A
git commit -m "更新画布"
git push origin main
```

正式发布前按发版流程整理 CHANGELOG、提升 VERSION 并提交；随后在 PowerShell 中运行（VERSION 中的版本号必须是尚未发布的新版本）：

```powershell
$releaseVersion = (Get-Content VERSION -Raw).Trim()
git tag $releaseVersion
git push --atomic origin main $releaseVersion
```

GitHub 负责构建和发布，服务器不会自动更新容器。镜像构建成功后，在服务器编排目录执行 `docker compose pull` 和 `docker compose up -d`，或使用 1Panel 拉取并重建。

- 推送代码到 `main` 会自动运行 **Build and Release**，构建 ZIP 并推送 Docker latest 镜像。ZIP 位于本次运行的 Artifacts；镜像位于 Packages。main 构建不创建正式 Releases。
- 正式发版时整理 `CHANGELOG.md`、更新根目录 `VERSION`、提交代码，再创建与 `VERSION` 相同的 `v*` tag 并推送。**Build and Release** 在 ZIP 与 Docker 均成功后，把 `jisu-canvas-web.zip` 上传到 GitHub Releases。
- Releases 自带的 **Source code** 是源码；1Panel 静态部署使用 `jisu-canvas-web.zip`。
- 统一流程会先发布节点插件，再发布 Docker 镜像；tag 另行触发文档镜像和 GitHub Pages。首次部署 Pages，进入仓库 Settings → Pages → Build and deployment，将 Source 设为 GitHub Actions。启用后，在失败的 GitHub Pages 运行详情右上角选择 Re-run jobs → Re-run all jobs；后续版本 tag 自动部署。默认站点地址为 `https://drunkard-baifeng.github.io/infinite-canvas/`，与 1Panel 部署独立。
- Docker 镜像发布到 `ghcr.io/drunkard-baifeng/infinite-canvas`，与 Releases 的 ZIP 是两种独立部署产物。原有独立构建已成功，统一流程与实际服务器部署仍需验证。

如果你希望在自己的机器或服务器上运行项目，可以直接使用 Docker Compose。

## 使用发布镜像

需先在本仓库 Actions 中成功运行 Build and Release，并将 GHCR 包可见性设为 Public；首次发布前请使用下方源码构建方式。

```bash
git clone -b main https://github.com/Drunkard-baifeng/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

启动后访问：

```text
http://localhost:3000
```

## 本地构建镜像

如果需要基于当前源码构建镜像：

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## 文档站镜像

文档站位于 `docs/` 目录，按带服务端能力的 Next.js standalone 应用单独构建，不打进主应用镜像。

使用发布镜像：

```bash
cd docs
docker compose up -d
```

基于当前源码本地构建：

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## 数据说明

当前主应用镜像使用 Nginx 托管 Vite 静态产物。画布、我的素材、生成记录和 AI API Key 默认保存在浏览器本地；第三方提示词由浏览器前端直连拉取，不需要额外挂载数据目录。

## 统计分析（可选）

项目**默认不接入任何统计**：不设置下列环境变量时，页面不会加载任何统计脚本，也不会发送任何外部请求。你在自己的部署上想查看流量时，设置对应环境变量即可，无需修改代码或重新构建镜像——镜像启动时会据此生成运行期配置。

统计按「每家一个独立变量」配置：**填了谁就启用谁，可同时启用多家**（例如 GA4 + 百度一起开）。仅支持 GA4 与百度，两者都只接受 ID，脚本地址由代码固定拼接，不接受任意脚本地址或内联 JS。

| 变量 | 说明 |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 衡量 ID（`G-XXXX`） |
| `ANALYTICS_BAIDU_ID` | 百度统计站点 ID（`hm.js?` 后面那串 hash） |

在 `docker-compose.yml` 的 `environment` 中配置（文件内已附注释示例），下例同时启用 GA4 与百度：

```yaml
services:
  app:
    image: ghcr.io/drunkard-baifeng/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

或使用 `docker run`：

```bash
docker run -d -p 3000:3000 \
  -e ANALYTICS_GA4_ID=G-XXXXXXXXXX \
  -e ANALYTICS_BAIDU_ID=e8263761cc5c32f5f7a855b8203b965a \
  ghcr.io/drunkard-baifeng/infinite-canvas:latest
```

单页应用的路由切换会自动向所有已启用的统计上报 pageview。

<Callout type="warn">
请只在你自己的站点上配置统计 ID，不要把 ID 提交进仓库；fork 或自托管本项目的用户默认不会产生任何统计。
</Callout>
